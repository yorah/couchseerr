# Couchseerr

A Kodi addon that shows seerr discovery rows on a TV, where every tile makes clear - without
focusing it - whether a title is owned, downloading, monitored, awaiting release, pending approval,
or not yet requested.

v2 adds requesting, playback of owned titles, and search. Clicking any tile - owned or not - opens a
detail listing on `mode=item` whose entries are the actions available for that title: play it,
request it, watch the trailer. Nothing plays or is requested on the click itself.

Still deliberately absent: issue reporting and a custom detail window. Visibly unfinished beats
silently broken - do not implement these without being asked.

Episode *requesting* is not on that list because it cannot go on it: seerr's `POST /request` accepts
a `seasons` array and has no episode-level endpoint at all, so this is not a missing feature but an
API that cannot express it. Season requesting and single-episode playback are implemented; episode
requesting never can be, short of a seerr API change.

seerr is the only backend. It already merges Radarr, Sonarr and the media server, so the addon needs
no Radarr/Sonarr credentials, no TMDb key, and no local library scan for status.

## Commands

```bash
./.venv/bin/python -m pytest -q        # tests (see note below)
python3 scripts/check_no_secrets.py    # no emails / private IPs / key-shaped strings in the tree
python3 scripts/check_no_kodi_imports.py
python3 -m compileall -q plugin.video.couchseerr
python3 tests/fixtures/generate.py     # regenerate fixtures (never hand-edit them)
```

Tests run through a `uv`-created venv because this environment has no working system pip. CI
installs pytest normally and uses plain `pytest`.

## Architecture

The core carries **no Kodi dependency**, so the logic that is easiest to get wrong is testable
without a device. Kodi-facing code is deliberately dumb.

```
plugin.video.couchseerr/resources/lib/couchseerr/
  errors.py client.py models.py state.py cache.py markers.py rows.py ui/spec.py  <- pure, no Kodi
  request_config.py library.py detail.py seasons.py actions/request.py          <- pure, no Kodi
  routes.py kodi/adapter.py kodi/jsonrpc.py kodi/dialogs.py                      <- Kodi adapter layer
```

`scripts/check_no_kodi_imports.py` enforces the boundary in CI.

**There is exactly one ListItem construction site** (`ui/spec.py`). Addons in this space duplicate
it across views, and that duplication is why their status handling drifts between views - the
precise bug this project exists to avoid. Do not add a second one.

## Hard constraints

- Addon id is `plugin.video.couchseerr`. Never change it - it keys `addon_data` and user widget paths.
- **Runtime dependencies: standard library only.** No `requests`, no third-party packages. HTTP goes
  through `urllib.request`.
- **Python 3.8 at source level.** No `match`, no `X | Y` runtime type syntax. `typing.Optional` /
  `typing.List`.
- **Kodi 19 through 22.** `addon.xml` declares `xbmc.python` `3.0.0`. Use `setProperty` in a loop,
  never `setProperties` (unreliable on 19). Never call `setInfo` directly - go through the adapter's
  `apply_info` shim, which prefers `InfoTagVideo` where available and falls back to `setInfo`.
- **Never swallow an error.** Nothing returns `None` to mean failure. The client returns a result or
  raises a typed error. A cache miss returning `None` is not a failure and is fine.
- **Determinism:** no `time.time()`, `datetime.now()` or `date.today()` inside pure functions.
  Clocks and dates are injected parameters.

## Test data

Fixtures under `tests/fixtures/seerr/` are **synthetic**, generated by `tests/fixtures/generate.py`,
and shaped to match a live seerr 3.4.1 instance. They deliberately cover cases a real instance cannot
supply on demand - every tile state, multi-server setups, populated and empty download status, and
error bodies.

Never capture fixtures from a live instance into the repo. CI fails if the committed fixtures drift
from what the generator produces.

## Secrets

`scripts/check_no_secrets.py` scans the tree for emails, private IP addresses, and key-shaped
strings. It is a CI gate.

Its `ALLOWED` set is for genuine synthetic placeholders only. **Never add a real-looking address,
hostname or key to it** - a single such entry makes the guard permanently blind to that string
everywhere. If a test needs a realistic value, construct it at runtime so no matching literal appears
in the source.
